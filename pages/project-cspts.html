Overview

โครงงานคืออะไร

CSPTS จำลองกระบวนการควบคุมโครงงานจริงของมหาวิทยาลัยให้เป็นระบบดิจิทัลเต็มรูปแบบ ไม่ใช่แค่ที่เก็บเอกสาร — ระบบรับผิดชอบความคืบหน้าโครงงาน การทำ task มติกรรมการ การมอบหมายอาจารย์ที่ปรึกษา คำร้องขอเปลี่ยนแปลง และ timeline ทั้งหมด โดยเอกสารเป็นเพียง "หลักฐาน" ว่างานเสร็จ ไม่ใช่แกนหลักของระบบ

🎯

ทุกฟีเจอร์ต้อง map กับขั้นตอนจริงในกระบวนการควบคุมโครงงาน — ถ้าหาคู่ในโลกจริงไม่เจอ แปลว่าไม่ควรมี

🇹🇭

UI เป็นภาษาไทยทั้งหมด ออกแบบให้นักศึกษาและอาจารย์ใช้งานได้ทันทีโดยไม่ต้องอบรม

Features

สิ่งที่ระบบทำได้

⚙️

Lifecycle Engine

โครงงานเดินผ่าน 6 milestone ตามลำดับ แต่ละ milestone มี task ของตัวเอง

🔗

Task Dependency

task ประกาศ dependsOn ทำเสร็จหนึ่งตัว ปลดล็อกตัวถัดไปอัตโนมัติ

✍️

Digital Decision

บันทึกมติแบบ append-only ตั้งค่า quorum และลำดับผู้อนุมัติได้จากข้อมูล

🔄

Change Request

ขอเปลี่ยนสมาชิก / ชื่อเรื่อง / อาจารย์ที่ปรึกษา / ขอบเขต พร้อมสายอนุมัติ

📋

Assessment Template

เกณฑ์ประเมินสอบแก้ไขได้จากฝั่ง admin แยก version ตามปีการศึกษา

🕓

Timeline + Audit Trail

Timeline เล่าเรื่องเชิงธุรกิจ DomainEvent บันทึกทุก transition แบบเทคนิค

📡

Live Update (SSE)

ข้อมูลอัปเดตแบบเรียลไทม์ผ่าน Server-Sent Events ไม่ต้องรีเฟรช

🔔

Notification + Email

แจ้งเตือนทั้งในระบบและทางอีเมลเมื่อมีความเคลื่อนไหวสำคัญ

Development Process

ลำดับการพัฒนา

  1. •

    ออกแบบ Domain Model

    Project → ProjectState → Task → TaskInstance

  2. •

    สร้าง Lifecycle Engine

    lifecycleRuntime.transitionTaskInstance() เป็นคอขวดเดียวของ state

  3. •

    เพิ่ม Task Behaviors

    FORM · FILE_UPLOAD · RUBRIC · MEETING · ADVISOR_ASSIGNMENT · APPLY_PROJECT_CHANGE

  4. •

    วาง Permission Layer

    DecisionPolicy แบบ data-driven ไม่ hardcode สิทธิ์ในโค้ด

  5. •

    เชื่อม Realtime + Deploy

    SSE สำหรับ live update และ Docker + LibreOffice สำหรับแปลงไฟล์

Challenges & Solutions

ปัญหาที่พบ กับวิธีแก้

เอกสารกระจัดกระจาย ไม่รู้ว่าติดที่ใคร

ทุกขั้นเป็น Task ที่มี state ชัดเจน TaskInstance บอกตรงว่ารออะไร/รอใคร

ลำดับขั้นตอนอยู่ในหัวคน จำเองต้องรู้เอง

dependsOn บังคับลำดับให้อัตโนมัติ ทำ task ถัดไปได้ก็ต่อเมื่อ dependency ผ่าน

ลายเซ็นอนุมัติหาย ตรวจย้อนหลังไม่ได้

Decision แบบ append-only บันทึกทุกมติถาวร ผูกกับ DomainEvent เสมอ

เปลี่ยนระเบียบทีต้องแก้โค้ดที

กติกาเก็บเป็นข้อมูล (DecisionPolicy) ไม่ใช่ if กระจายในโค้ด แก้ข้อมูลไม่ต้อง deploy ใหม่
