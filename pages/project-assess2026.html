Overview

โครงงานคืออะไร

assess2026 เก็บคะแนนแบบสำรวจชีพจรองค์กรจากบุคลากรกว่า 1,000 คน แล้วสรุปเป็นค่าเฉลี่ยรายหน่วยงานให้ผู้บริหารดูภาพรวม anonymity คือหัวใจของระบบ ไม่ใช่ feature เสริม — ผู้ถูกประเมินต้องระบุตัวผู้ประเมินไม่ได้เด็ดขาด ระบบไม่ใช่เครื่องมือประเมินผลงานรายบุคคล ไม่ใช่ระบบ HR/payroll และไม่ใช่ survey builder ทั่วไป (มี 3 ชุดตายตัว แก้ข้อคำถามได้ แต่สร้างชุดใหม่ไม่ได้)

🕶️

คำตอบแยกออกจากผู้ใช้เป็นคนละตารางตั้งแต่ระดับ schema ไม่มี foreign key เชื่อมกลับ — anonymous โดยโครงสร้าง ไม่ใช่โดยกฎ

📥

Import-first: admin นำเข้ารายชื่อ + หน่วยงานล่วงหน้า ผู้ใช้แค่ยืนยันตัวตนกับ record ที่มีอยู่ ป้องกันคนนอกปั่นคะแนน

Challenges & Solutions

ปัญหาที่พบ กับวิธีแก้

ถ้าเก็บ userId ไว้กับคำตอบ ผู้ดูแลระบบย้อนดูได้ว่าใครให้คะแนนหัวหน้าเท่าไร คนไม่กล้าตอบตามจริง

แยก Response กับ Participation เป็นคนละตาราง ไม่มี foreign key เชื่อมกัน และตัด timestamp เหลือแค่ @db.Date กัน join ย้อนกลับ

เปิดสมัครเสรีจะโดนคนนอกปั่นคะแนน และหน่วยงานที่กรอกเองอาจเพี้ยนจน aggregate ไม่ตรง

Import-first — admin นำเข้ารายชื่อ + หน่วยงานก่อน ผู้ใช้แค่จับคู่ตัวเองกับ record ที่มีอยู่แล้ว

Server Actions เป็น public POST endpoint เรียกตรงได้โดยไม่ผ่าน UI

ทุก action ที่เขียนข้อมูลเรียก auth() ซ้ำในตัวเอง และ action ฝั่ง admin เช็ค role === "ADMIN" ซ้ำอีกชั้น

K1/K2 มี target เป็น NULL — ถ้าใช้ unique index ปกติ Postgres จะยอมให้ NULL ซ้ำ ทำให้ส่งซ้ำได้

เขียน raw SQL migration บังคับ unique index แบบ NULLS NOT DISTINCT เพราะ Prisma schema สร้าง syntax นี้เองไม่ได้
