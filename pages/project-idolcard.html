Overview

โครงงานคืออะไร

เครื่องมือสำหรับพ่อค้าแม่ค้าที่ขายการ์ด/ของสะสมและรับออเดอร์จาก IG/Twitter — ลูกค้าพิมพ์ชื่อบัญชีโซเชียลค้นหาสถานะออเดอร์และยอดเงินคงเหลือได้เองแบบเรียลไทม์ ไม่ต้องสมัครสมาชิก ส่วนแอดมินจัดการออเดอร์ ยอดมัดจำ และนำเข้าออเดอร์เป็นชุดผ่าน dashboard

🚫

ระบบนี้ ไม่ใช่ ตะกร้าสินค้า/เช็คเอาต์ออนไลน์ ไม่ใช่ payment gateway และไม่ใช่ระบบบัญชีเต็มรูปแบบ — ลูกค้าไม่ได้สั่งซื้อผ่านระบบ แค่เช็คสถานะ

💬

ปัญหาเดิม: รับออเดอร์ผ่านแชท/คอมเมนต์ ลูกค้าถามซ้ำว่า "ของถึงไหนแล้ว มัดจำครบยัง" แอดมินต้องไล่เปิดแชทหาทีละคน

Features

สิ่งที่ระบบทำได้

🔍

Order Search

ลูกค้าค้นหาออเดอร์ของตัวเองด้วยชื่อบัญชี IG/Twitter โดยไม่ต้องสมัครสมาชิก

📡

Realtime Update

Supabase Realtime subscribe การเปลี่ยนแปลง เมื่อแอดมินอัปเดตออเดอร์ หน้าลูกค้าเด้งข้อมูลใหม่ทันทีโดยไม่ต้อง refresh

🗂️

Admin Dashboard

สรุปสถิติออเดอร์ และจัดการรายการออเดอร์ทั้งหมด

📥

Batch Import/Export

นำเข้า/ส่งออกออเดอร์เป็นไฟล์ Excel ด้วย xlsx

💰

Payment Ledger

ติดตามยอดมัดจำและยอดคงเหลือ แยกเก็บรายการปรับยอดเป็น ledger ไม่แก้ยอดรวมตรง ๆ

🔐

Admin Authorization

ทุก Server Action เช็คสิทธิ์ผ่าน requireAdmin() ก่อนแตะข้อมูลทุกครั้ง สิทธิ์อ่านจาก ADMIN_EMAILS ใน env

Order Lifecycle

สถานะของออเดอร์

  1. 1

    RESERVED

    รับออเดอร์เข้าระบบ

  2. 2

    ORDERED

    สั่งของแล้ว

  3. 3

    READY_TO_SHIP

    พร้อมจัดส่ง

  4. 4

    COMPLETED

    ส่งมอบเรียบร้อย (หรือ CANCELLED หากยกเลิก)

payment_status แยกอิสระจากสถานะออเดอร์: PENDING → DEPOSIT → PAID

Development Process

ลำดับการพัฒนา

  1. •

    ออกแบบ Schema

    ตาราง orders, profiles, RLS ใน supabase_schema.sql

  2. •

    สร้าง Public Search API

    route ที่ควบคุม query แทนการอ่านตารางตรงจากฝั่งลูกค้า

  3. •

    วาง Admin Authorization

    requireAdmin() ตรวจสิทธิ์จาก ADMIN_EMAILS ก่อนทุก Server Action

  4. •

    เพิ่ม Payment Ledger

    แยก migration สำหรับคำนวณยอดคงเหลือและบันทึกรายการปรับยอด

  5. •

    เปิด Realtime + Batch Import

    เปิด postgres_changes channel และเพิ่มนำเข้า/ส่งออกออเดอร์เป็น Excel

Challenges & Solutions

ปัญหาที่พบ กับวิธีแก้

ลูกค้าถามซ้ำ ๆ ว่าของถึงไหนแล้ว มัดจำครบยัง แอดมินต้องไล่เปิดแชทหาทีละคน

ลูกค้าค้นหาสถานะเองผ่านชื่อบัญชีโซเชียล เห็นสถานะ+ยอดค้างชำระทันทีโดยไม่ต้องถาม

อัปเดตออเดอร์แล้วลูกค้ายังเห็นข้อมูลเก่า ต้อง refresh เอง

Supabase Realtime subscribe การเปลี่ยนแปลง หน้าลูกค้าเด้งข้อมูลใหม่ทันที

ลูกค้าอาจอ่านออเดอร์ของคนอื่นได้ผ่าน anon key

ตั้ง RLS policy เป็น USING (false) บังคับให้ทุกการค้นหาผ่าน API route ที่ควบคุม query เท่านั้น

แก้ price_total ตรง ๆ ทำให้ตรวจสอบยอดปรับย้อนหลังไม่ได้

แยกรายการปรับยอดเป็น payment ledger ต่างหาก ไม่แก้ price_total ตรง ๆ
